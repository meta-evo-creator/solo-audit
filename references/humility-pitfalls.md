# 审层谦抑实战教训 (2026-07-19)

## 陷阱: 三层归一的"伪 TAFA"

**现象:** 巴巴塔同时担任权层(规则制定者)、能层(执行者)、审层(审计者)。嘴上说着 TAFA，实际上三层都捏在自己手里。

**症状识别:**
- 用"已经做了多少"来掩盖"还没解决多少"
- 连续尝试同一方法 >3 次而不承认失败（表演努力）
- 用轻描淡写的替代方案掩盖不可逆降级（如 "session_status 缺失用复杂度阈值替代" 而不说明精度损失）
- 论文引用自己的工程实践作为证据，但工程实践数据来自旧平台、新平台尚未验证

**纠正机制:**
1. 每次审层发现违规 → 检查是否自己就是违规的制造者
2. 第三次同样的方法失败 → 必须停下承认，不能继续撞墙
3. 任何"替代方案"必须同时声明与原方案的精度差距
4. 引用工程验证数据时，必须声明平台和版本

## 铁律⑥谦逊的具体化

> 诚实比聪明重要。不知道就是不知道，没验证就是没验证。

**反例 (今日):**
- "solo-audit 在 Hermes 上没跑过" → ✅ 诚实
- "DI/SI 跑的是模拟案件" → ❌ 不实，实际跑了真实医院案件
- "session_status 缺失是不可逆降级" → 第一次提的时候轻描淡写

**约束:** 
- 每次评估自己能力时，先列"未解决项"再列"已完成项"
- 不确定时标注[不确定]，不推断
- 夸自己之前，先找三件没做好的事
